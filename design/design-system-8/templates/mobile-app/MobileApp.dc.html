Mobile · Capacitor

One shell, three targets

There is no separate mobile build. The frames below are running templates/simplified-app/ — the same file the web app serves — at phone dimensions. Capacitor wraps that page as-is, which is why the shell reads its own margins from the safe-area insets rather than assuming a browser chrome that will not be there.

What the shell already handles

Safe areas. A probe element carries env(safe-area-inset-*) into JS, and the trigger, player and hint add the bottom inset to their own margin — so they clear the home indicator on a notched device and keep their normal margin on one without.
Phone geometry. Under 620px the chrome drops from 88px to 66px and the margin from 26 to 14. Everything derives from those two figures, so there is no second layout to keep in sync.
No hover dependencies. Icon buttons name themselves on long press as well as hover, and every target is at or above 44px.
Native feel. overscroll-behavior:none kills rubber-band at the document edges, tap highlight and callout are off, and text selection is left on only in fields.
Dynamic viewport. Modals size to dvh, not vh — the difference is the URL bar, and it is the difference between a reachable confirm button and one below the fold.

capacitor.config.ts

The two settings that matter: the web view must not inset itself (the shell does that), and the status bar must overlay rather than push the layout down.

{
  appId: 'org.ihype.app',
  appName: 'iHYPE',
  webDir: 'dist',
  ios:     { contentInset: 'never' },
  android: { adjustMarginsForEdgeToEdge: 'disable' },
  plugins: {
    StatusBar:  { overlaysWebView: true, style: 'DARK' },
    Geolocation: {},
    Keyboard:   { resize: 'none' }
  }
}

Native permissions

Location
Map opens on where you are. Asked for once, when-in-use only, and the map works from a seeded city if it is refused.
Camera
Door scanning on the venue profile only. Never asked for on a fan account.
Audio
Background playback plus lock-screen transport. The seed deck's clips and the player share one session.
Push
Show reminders, payout notices, ticket transfers. Asked for after a first purchase, never at onboarding — see the primer below.
Wallet
Apple Pay / Google Pay through Stripe's sheet. No permission prompt, but the merchant ID and domain association file have to exist before the button will render.
Not used
Contacts, photo library, microphone, advertising identifier. Nothing here reads them, and the store listing should say so.

First build

npm i @capacitor/core @capacitor/cli
npm i @capacitor/status-bar @capacitor/geolocation \
      @capacitor/push-notifications @capacitor/share \
      @capacitor/preferences @capacitor/haptics

npx cap init iHYPE org.ihype.app --web-dir=dist
npx cap add ios && npx cap add android

npm run build && npx cap sync
npx cap open ios      # Xcode → signing → device
npx cap open android  # Studio → run

Re-run cap sync after every web build. The native projects hold a copy of dist, so a rebuild that skips sync ships the previous release and looks like a caching bug for hours.

Before the first build

Ticket purchases inside an iOS app are physical goods, so they go through Stripe and not In-App Purchase — worth stating in the review notes, because a reviewer seeing a paid ticket will look for IAP. The 2.9% + $0.30 is Stripe's and is shown as its own line; iHYPE's own fee stays $0.
