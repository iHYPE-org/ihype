Mobile · Permissions

Ask at the moment of use

A permission has one OS prompt per install. Spend it badly — at onboarding, with no context — and it is gone for good. So every capability gets our own sheet first, which can be declined harmlessly, and every refusal has a path that still works. Six capabilities, three states each.

Doors at 8. We'll remind you.

Three things only: when a show you hold a ticket for is close, when a promoter payout lands, and when someone sends you a ticket. Nothing else, ever.

Fires after first ticket · not onboarding
See what's on near you

The map opens where you are instead of where we guessed. We ask for the coarse, city-level version — not your exact position — and only while the app is open.

Fires on first Map open
Scan them in at the door

Point the camera at a fan's ticket code and it checks in. Nothing is recorded and no image is stored — the frame is read and dropped.

Venue accounts only · never asked of a fan
Pay in two taps

Apple Pay and Google Pay run through Stripe, so we never see your card. Face ID confirms it. Card entry is always there if you'd rather.

No OS prompt · needs merchant ID on file
Share it, earn from it

Your HYPE Link carries your code. Anyone who buys through it puts you in the 10% promoter pool for that show. Any account can do this — there is nothing to sign up for.

No OS prompt · falls back to clipboard
Your ticket works with no signal

Venues are basements. Once a ticket is yours it is stored on the device and drawn from the code itself, so the wallet opens in airplane mode.

Fires on first ticket · IndexedDB

When they say no

A refusal is a valid answer, so none of these is an error state. The feature is replaced by a manual equivalent, the route to Settings is offered once and never nagged, and no capability is load-bearing for buying or holding a ticket.

Push denied
Nothing is lost

Every notice still arrives in the in-app centre with an unread dot on Me. The show page shows a "Doors 8pm" line in place of the reminder toggle.

Location denied
The city picker becomes the control

The map opens on the home city from Settings and the "Near me" chip is replaced by that city's name, tappable to change. No empty state.

Camera denied
The scan reverses

The fan shows their code and the door taps it in from the guest list instead. Slower, works, and the venue is never blocked at 8pm by a permission.

Wallet unavailable
Card entry, same sheet

If the device has no wallet the button is not rendered at all — never rendered-then-failing. Stripe's card fields take its place in the same position.

No share sheet
Copy, with proof it happened

The link goes to the clipboard and the button becomes "Copied" for two seconds. The code in the link is identical, so the promoter share still tracks.

Storage refused
Online-only, said plainly

The wallet carries a one-line note that tickets need signal to open, so nobody discovers it in a queue. Codes re-fetch the moment there is a connection.

The one rule that outranks the rest

Buying a ticket and opening a ticket must work with every one of these refused. If a flow you are building breaks when all six are denied, the flow is wrong — not the fan's answer.
